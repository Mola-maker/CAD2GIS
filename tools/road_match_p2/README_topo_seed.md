## 方法

1. **缆线汇合点图**（`build_cable_graph`）：端点 snap（2 m）聚类 + 内部交点分裂，
   度数≥3 为汇合点。hutabohu：6 条缆线 → **2 个 3 度汇合点**（A: lines 0/2/3，
   B: lines 1/4/5），基线距离 1628.9 m。
2. **OSM 路口图**（`build_osm_graph` + `cluster_osm_junctions`）：按共享 node id
   计度数（way 内部经过计 2、端点计 1），217 个度数≥3 路口；把间距 ≤30 m 的路口
   合并为 **170 个超路口**（吸收 OSM 把一个物理路口拆成多个相邻节点的短边——
   真值 B 点实际落在两个相距 8 m 的 OSM 节点之间，不合并则对不上）。
3. **基线配对**（Li & Briggs 点模式匹配）：缆线汇合点对的距离是 scale=1 下的
   不变量；对每个有序 OSM 超路口对满足 |Δ基线| ≤ max(30 m, 8%) 者，
   θ = bearing(o1→o2) − bearing(c1→c2)，t = o1 − R(θ)·c1，直接解出相似变换；
   两端点各做交会边方位角序列**子集匹配**（缆线 deg-3 可对 OSM deg≥3 的任意
   3 条边，容差 25°）验证打分。score = 平均角残差 + 0.5×最大角残差
   + 0.5×基线长度残差(m) + 10×悬空边矛盾罚分。
4. **单点兜底通道**：若基线通道零产出（如汇合点 <2），退化为单汇合点方位角
   对齐 + 其余汇合点位置验证（本基线未触发）。
5. **抛光**：复用 P1 的精确 F1 定义与爬山调度（5 m/0.5° ÷2.5 递减至 <1 m），
   Top-10 假设各自独立抛光，取 F1 最高者。

## 评估量核算约定（诚实口径）

1 次评估 = 对 1 个 (θ,t) 假设做 1 次 F1 评分。

- P1 全程 = 17,446,800 栅格评估（粗 72 + 细 33 幅 FFT 相关图 × 搜索域掩膜内
  166,160 个有效 5 m 平移像素，按 P1 索引公式精确重算）+ **163** 次精确抛光评估
  （从 P1 `result.json` 的 `top5_fine[0]` 按同一爬山调度确定性重放计数）
  = **17,446,963**。
- P2 = 10 次种子精确评分 + 1,657 次 Top-10 抛光爬山评估 = **1,667**。
- 注意：若只比"精确 F1 评估"（P2 1,667 vs P1 抛光 163），P2 反而更多——P1 的
  精确阶段便宜是因为 FFT 扫描已承担了搜索成本。5% 标准在"全程评估量"口径下
  成立（0.0096%），两口径都写入 `results/topo_hutabohu.json` 的 `eval_counts`。

## 已知限制 / 未解决项

- **仅 2 个缆线汇合点**：本基线拓扑信息极简，单条基线 + 角度验证即足够；
  更复杂的图纸（更多汇合点）可用同一框架组合多条基线，未实现。
- **旋转残差 0.088° 略大于 P1 的 0.008°**：种子初值精度（基线方位角受路口
  定位误差影响 ~0.7°）限制了抛光起点，但远优于 5° 标准。
- **scale 仍锁 1**（与 P1 相同）；若 CAD 含单位误差，基线长度容差 8% 可吸收
  部分比例误差，但未显式解算比例维。
- 方位角容差 25°、超路口半径 30 m 是按本基线调试的经验值；对路口极密或
  图纸严重简化的数据可能需要放宽，放宽会增加假种子（成本仍远低于网格扫描）。
- 未接入 `gcp_workflow.py` 候选框架（同 P1，留后续集成）。
