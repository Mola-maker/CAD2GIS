本轮输入为 `E:\source_dwg` 的九张实际 DWG。现场证据与可打开成果索引位于

旧版已注入转换技能未作为执行依据；本轮依据实际安装包、源码和独立核验结果更新技能。

## 当前最需要提升的转换边界

优先修复 **不可变 CAD 事实 → 业务解释 → 派生几何** 的分离。把接头盒移动到杆位、
把线端拉到设施、把无效边界修成合法面，都属于会改变几何的业务操作，不能混在分类中
自动发生后仍声明原图精度保留。现场 Taipa 的接头盒移动超过 12 m；Lamteh 的边界修复
删除了约 97.7 m 的尖刺。来源记录正确只说明变化可以追溯，并不说明变化可接受。
Manado 主图线路吻合，但其 EMR28560 分区有约 7.91 m 的端点桥接，线路长度增加约
7.36 m。因此主图与每个分区都必须独立核验并进入交付清单，不能只检查主 GPKG。

本轮已修正派生线路/边界及其继承成果的记录、补上真实位移和损失指标、加入边界待审项。
端点修复现在要求源端点、目标源设施、完整变更记录及输出一致，禁止曲线被该规则压直。
下一轮应进一步把这些操作从默认分类器拆到独立候选与验收阶段。

## 分阶段实施计划

### P0：一次读取，冻结事实，全程重用

- 为 canonical `ConversionRequest` 增加经过哈希、读器版本、原 DWG 和完整性检查的
  source snapshot 输入；onboarding、语义编译和最终转换读取同一份冻结记录。
- 明确区分 native reader 快照与测试注入记录，禁止调用方自行把后者标成 native。
- 将 basename 等展示元数据与几何/文字内容绑定分别记录，迁移必须留下明确收据。
- 当前 `ingest` 已有 records port，但公共转换接口尚无正式冻结快照参数，不能通过
  monkeypatch 或改 inventory hash 绕过准入。
- 验收：冻结后禁止再次调用 DWG reader；同输入/配置重复转换的逻辑几何与业务字段相同；
  修改一字节、换读器、缺失 sidecar 或伪造源权限均拒绝。真实 MTEXT 不稳定案例必须覆盖。

### P0：AI 只改解释，几何修复单独立项

- 源坐标、曲线参数、原始文字、native length、CRS/GEODATA 留在不可变事实层。
- AI 通过 SQLite 的分页/过滤/空间索引读取实体和候选上下文；写入对象限于已观察的
  实体、分类、标签候选和已登记策略，不提供任意 SQL 写入口。
- `preview → exact preview hash → CAS commit → idempotent compile` 继续作为唯一写通道。
- 设备与支撑点同位首先记录为关系；几何移动另产候选图层与逐对象变更清单。
- 原始边界与 repaired boundary 同时可读；面修复报告面积、顶点、组件、洞和
  boundary Hausdorff 差异。存在有损修复必须保持待审，不能仅通过修改 lineage 转为合格。
- 邻近数字与设备的匹配保留数字源实体、原文、距离和待审关系。Tinggar 的 31 个
  数字标签已修正为派生来源，不能把邻近文字误称为直接块属性；来源可核对也不等于
  已确认数字在工程中的含义。相同 token 数量的不同标注结构应分别归类，保留完整覆盖门。
- 验收：AI 提案不改变事实数据库哈希；过期 revision、跨图候选、伪造杆位和弧线压直
  均拒绝；原图层在任何修复前后都可完整导出与对照。

### P0：可视核验成为交付门的一部分

- Web 分别提供完整原图、展开实例域、业务成果域，显示来源与渲染不支持清单。
  当前左窗只回溯已交付要素，不能用于证明无遗漏。
- 提供同坐标域叠加/闪烁、全图与业务范围视图、位移箭头、差异对象定位、字段前后值。
- 线路按源 ID 重组分段后比较几何与长度，另查顶点图和连接关系；未交付实体必须有去向。
- 将 native CAD 原生图像与重建矢量视图分开标注；字体、线型、hatch、proxy、裁切等
  不能由控制点折线绘图冒充已验证。
- 验收：本轮九张图及刻意注入的偏移、漏对象、错标签、弧线压直、块变换错误均能
  被独立审计定位。将不支持、装饰图形和真实资产缺失分别计数。

### P1：统一人工 GCP 的预览和正式拟合

- Web 与最终转换调用同一拟合引擎、同一目标 CRS、同一控制点权重和过滤规则。
  当前浏览器相似变换预览与正式平移模型不一致；界面已标注，不能用预览残差验收。
- 把测量/权威控制点导入、来源、坐标系、精度、训练/独立检查角色做成正式数据模型。
  OSM 相对参照单独标记；输入经纬度不自动获得测量来源身份。
- 将可选 `gcp prepare` 依赖的 operator 正式打包或替换为维护中的接口，避免现场依赖旧脚本。
- 验收：独立检查点不进入拟合；预览与新 run 对同一批控制点产生一致残差；缺少控制点
  或控制点分布不足不产生绝对精度合格声明。当前这批图尚无独立测量 GCP。

### P1：冷索引、编译与 debug_mcp 可观测

- 大图首次建索引应是可取消、带阶段进度和资源预算的显式任务。现场首次查询可能耗时
  约 70 s；返回 8 KiB 不代表建索引的时间和内存也受到 8 KiB 限制。
- `debug_mcp` 保留解释器、真实模块路径、包/协议/完整工具 schema 摘要、允许目录、
  reader、工件哈希与错误码；stdout 仅协议，诊断走 stderr。
- 安装证明包含 wheel SHA、逐文件 wheel↔site-packages↔checkout 比对、隔离 stdio 测试。
  server 不能证明宿主注入了哪个 skill，需要另验客户端缓存 bundle。
- Windows 原子发布前恢复输出目录正常继承权限，保证用户可读，而非只对沙箱账户可读。

## SQLite 与 Redis 的定位

SQLite 保存本地源查询索引、语义 revision、编译任务、取消栅栏和 outbox。源 DWG/冻结
快照是原始事实，语义状态有版本和来源绑定；发布的 GeoPackage 是运行产物。不能把
任意查询缓存当原始事实，也不能让 Redis 的过期键决定提案是否已经提交。

Redis 只在多进程/多机任务分发、短期缓存和状态通知需求出现后引入。任务是否提交、
revision 是否有效、哪一个产物被接受仍由持久数据库与内容哈希判断。本次单机转换
不需要 Redis。将来替换协调数据库需通过专门 repository/transaction adapter，不能
为了提高查询速度另造第二套语义真相。

## 验收声明

文件哈希与 GPKG integrity、转换状态、几何保真、字段保真、视觉完整性、绝对定位精度
分别验收。`audit_status=PASS` 仅表示该审计覆盖的工件一致，不会把 `CONDITIONAL`、
unsupported、未解释差异或有损修复升级为合格工程交付。
