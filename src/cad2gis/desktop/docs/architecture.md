# 应用架构 · 0.5

## 界面与安装端
Windows 原生启动器启动独立 Python 运行时，打开本地工作台。界面复用 Framework7 的 iOS 风格分页、弹窗与交互组件；粉蓝配色、半透明面板和轻缓动效使用项目自己的样式。系统开启减少动态效果时关闭非必要动画。

Windows / Linux 本机和 Android 远程客户端使用同一服务 API。原有命令行与 MCP 插件入口保留。桌面 AI 配置由服务端持久保存，Windows 使用当前用户 DPAPI 加密。

## 智能体层
Pydantic AI Core 负责模型适配、工具循环、参数校验、重试和请求预算。桌面会话层将消息、计划、过程和用量保存在 SQLite。每个任务以隔离子进程连接现有 CAD2GIS MCP 服务；配置同时传给标准转换任务和智能体，避免界面已配置而转换引擎没有密钥的问题。

完整工具目录由 MCP 动态发现，不复制转换算法。模型配置测试执行一次真实工具往返；任务运行支持文本增量、工具事件和停止。

## 转换与审查层
既有 CAD2GIS 引擎继续承担读取、语义证据、几何处理、坐标转换、OSM 相对匹配、SVG 提取和交付验证。标准流程保持 OSM 匹配与 SVG candidate。人工 GCP 先预览，明确要求后再应用二次匹配。

OSM 与 SVG 页面复用现有审查服务，并绑定当前会话的结果标识。SQLite 可视化通过只读连接、SQL 授权器、查询时间预算及分页控制数据量。

## 边界与部署
本地启动使用一次性登录链接和 HttpOnly 会话。远程部署要求 HTTPS 与登录密码；远程页面不能修改模型凭证。Host / Origin 校验、项目根目录约束、配置目录隔离、原有语义审核和交付门禁继续生效。

安装包自带运行时和本地前端资源；连接模型、在线 OSM 数据仍需要网络。Figma 设计与图像生成只用于开发，运行软件不依赖 Figma 服务。
